# Openhash-Gopang / Passport

**혼디(Hondi) 오픈해시 기반 디지털 여권 프로젝트**

## 한 줄 요약

혼디는 신원정보를 새로 발급하거나 서명하지 않는다. 정부(모바일 신분증, 전자증명서 발급유통시스템)가
이미 서명한 증명서를 사용자 IDV에 원본 그대로 보관했다가 필요한 기관에 재제출하는 데이터 금고이며,
동시에 **"누가 언제 어디서 어떤 증명서를 왜 누구에게 제출했는지"를 기록·축적**한다. 이 축적된
제출 이력이야말로 혼디의 최대 장점이다 — 데이터가 쌓일수록 불요불급한 절차·기관이 자연히 드러나고,
증명서의 발급·제출 자체를 줄이는 근거가 된다. 국제 확장(Phase 1/2)에서는 이 같은 원칙(국가 시스템
대체 아님, 감사·투명성 레이어로만 기여)을 ICAO/eIDAS 등 기존 국제표준 위에서 반복한다.

국가의 발급 권한을 대체하지 않는다. 국가 시스템 위에 얹히는 데이터 금고 + 제출 이력 분석 레이어다.

## 대표 시나리오 — 위치기반서비스 등록 (2시간 → 1초)

혼디 패스포트 시스템이 지향하는 바를 가장 잘 보여주는 예시다.

| | As-Is (현재) | To-Be (혼디 적용 후) |
|---|---|---|
| 절차 | IT 기술 전문가가 각종 신청서 작성, 등록세 납부, 여러 정부기관을 돌며 각기 확인서 발급받아 이곳저곳 제출 | 사용자가 "위치기반서비스 등록" 버튼을 클릭/터치 |
| 소요 시간 | 약 2시간 | 약 1초 |
| 내부 동작 | 사람이 매 단계 직접 확인·이동·제출 | PDV/IDV에 저장된 제반 증명서(사업자등록증·법인등기부등본 등)가 자동 전달, GDC 결제 자동 처리, 등록 신청·승인 완결 |

핵심은 "정부가 서명한 증명서를 미리 IDV에 모아뒀기 때문에, 새로 발급받으러 다닐 필요가 없다"는
Phase 0의 데이터 금고 모델이 그대로 이 시나리오의 기반이 된다는 점이다.

## 핵심 원칙

- **진본성은 정부가, 무결성·시점 증명은 혼디가**: 발급 시점에 거짓이 아님은 정부 전자서명이 보장,
  혼디/오픈해시는 사후 위변조 안 됨과 "언제부터 보유했는가"만 감사 가능하게 만든다
- **"서버는 평문을 못 읽는다"**: 신원정보 원본은 각국 로컬 시스템 + 사용자 기기(IDV)에만 존재,
  정부 발급 원본 포맷 그대로 opaque 보관 — 혼디가 재서명·재포장하지 않는다
- **제출 이력은 개인별이 아니라 집계·패턴으로만**: "누가 언제 어디서 무엇을 왜 누구에게 제출했는지"의
  축적이 최대 자산이지만, 외부 노출은 반드시 가명화 해시 기반 집계 단위로만
- **절차가 기관보다 먼저**: 국가별 발급 절차 차이를 흡수하는 것은 혼디 지갑, 오픈해시는 결과(해시)만 앵커링

## 3단계 로드맵

1. **Phase 0 — 국내 신뢰 구축**: 혼디는 발급기관이 아니라 IDV 데이터 금고 — 모바일 신분증/
   dpaper.kr API 연동으로 정부 발급 증명서를 보관·재제출, 그 제출 이력을 축적 (제주 → 전국,
   hondi 인프라 확장)
2. **Phase 1 — 국제표준 정합**: ICAO DTC / ISO 18013-5 / eIDAS 2.0 참조 구현체화
3. **Phase 2 — 감사·투명성 레이어**: 오픈해시를 국가 PKI 루트 대체가 아닌 시점 증명 + 폐기·신뢰목록
   이력 앵커링 레이어로 통합

자세한 내용은 [ROADMAP.md](./ROADMAP.md) 참고.

## 관련 저장소

- `hondi`(구 gopang) — 제주도청 AI 어시스턴트, IDV/PDV 인프라 (Phase 0의 기반)
- `gdc` — GDC 과금/지갑 인프라 (device-link 인증 흐름 재사용 대상)
- `users` — 사용자 GUID/PDV 관리

## 비범위 (Non-goals)

- 국가 발급 권한을 오픈해시가 대체하는 것 (정치적으로 불가능하며 시도하지 않음)
- 생체정보 원본을 국경 간 전송하는 것 (ZK 증명으로만 대체)
- 물리 여권의 즉각적 폐지 (병행 사용 전제)
- 개인별 제출 이력의 식별 가능한 형태 외부 노출 (집계·패턴 단위만)
